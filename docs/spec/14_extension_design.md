# 브라우저 확장 설계

> 쿠팡 장바구니 자동 담기를 담당하는 사주라 브라우저 확장의 확정 사항.
> 기능 규칙 원본은 `04_feature_spec.md` §7, API 계약은 `07_api_spec.md` §7이다.

---

## 1. 목적과 산출물

- 발주 확정 품목을 점주의 쿠팡 장바구니에 자동으로 담는다.
- **사주라 서버는 쿠팡 자격증명을 수집·저장하지 않는다.** 담기는 점주 본인 브라우저에서 수행하므로 서버가 쿠팡 계정에 접근할 일이 없다.
- 산출물은 PWA와 별개 배포 단위인 Chrome 확장(Manifest V3)이다.

| 항목 | 결정 |
|---|---|
| 이름 | 사주라 확장 (Sajura Extension) |
| 플랫폼 | Chrome Manifest V3 |
| 배포 단위 | PWA와 분리. 저장소 디렉터리도 분리한다 |

---

## 2. 권한 범위

| 항목 | 값 |
|---|---|
| `host_permissions` | `*://*.coupang.com/*` 만 |
| `externally_connectable.matches` | 사주라 PWA 도메인만 |
| 그 외 | `<all_urls>`·`tabs` 전체 권한·쿠키 접근을 요청하지 않는다 |

`window.postMessage` 릴레이 대신 `externally_connectable`을 쓴다. 우리 도메인에 content script를 주입하지 않아 공격면이 작다.

---

## 3. 실행 흐름

```text
[PWA]  발주 확정 → 품목 목록(재료명·수량·단위) 확보
  ↓ chrome.runtime.sendMessage (externally_connectable)
[확장]  쿠팡 검색 → 결과 카드 파싱 (§4 화이트리스트 필드만)
  ↓
[PWA]  POST /api/orders/{order_id}/automate/match   (JWT)
  ↓
[BE]   LLM 호출(§5) → 품목별 상품 1개 선택
  ↓
[PWA]  선택 결과를 확장에 전달
  ↓
[확장]  쿠팡 장바구니 담기(결정론 셀렉터) → 품목별 성공·실패 수집
  ↓
[PWA]  POST /api/orders/{order_id}/automate/result → orders.status 갱신
```

- 품목별로 왕복하지 않는다. 전체 품목의 검색 결과를 한 번에 보내고 선택도 한 응답으로 받는다.
- LLM 호출은 발주 1건당 1회다.
- 서버가 브라우저를 조작하지 않는다. 서버는 판단만 하고 실행은 확장이 한다.

---

## 4. 확장이 서버로 보내는 데이터

확장이 수집·전달하는 필드를 아래로 한정한다. 페이지 HTML 전체·쿠키·로그인 정보·주문 이력은 보내지 않는다.

```json
{
  "item_id": "uuid",
  "query": "돼지고기 삼겹살 냉장",
  "results": [
    {
      "product_name": "○○농장 삼겹살 1kg",
      "price": 18900,
      "unit_text": "1kg",
      "product_url": "https://www.coupang.com/vp/products/..."
    }
  ]
}
```

로그인 상태의 쿠팡 페이지에는 이름·배송지·최근 주문이 함께 존재한다. 화이트리스트를 두지 않으면 그 값이 외부 LLM 제공자로 나간다 — `12_security.md` §3 최소 수집 원칙 위반이다.

---

## 5. LLM 사용 경계

LLM은 **무엇을 담을지 고르는 데만** 쓴다. 담는 동작은 확장이 고정 셀렉터로 수행한다.

| 단계 | 수행 주체 |
|---|---|
| 재료명 → 쿠팡 검색어 변환 | LLM |
| 검색 결과 중 상품 1개 선택 (용량·묶음 환산 판단) | LLM |
| 검색 페이지 열기 | 확장 (URL 조립) |
| 장바구니 담기 클릭 | 확장 (고정 셀렉터) |
| 담김 여부 확인 | 확장 |

- LLM 제공자·모델은 미확정이다. API 키는 서버 환경변수로만 두고 Frontend·확장에 노출하지 않는다.
- 셀렉터가 깨지면 해당 품목을 실패로 처리한다. 재시도하지 않는다 (`04_feature_spec.md` §7.2).

---

## 6. 로그인 상태

확장은 쿠팡 로그인 여부를 확인하지 않고, 로그인을 요구하지도 않는다. 비로그인 상태에서 담긴 장바구니를 계정으로 옮기는 것은 쿠팡의 동작에 맡긴다.

---

## 7. 실패 처리

`04_feature_spec.md` §7.2를 따른다. 재시도 없이 품목별 성공·실패를 나누어 점주에게 수동 처리 안내를 표시한다.

확장 고유의 실패 사유를 아래로 구분한다.

| 사유 | 처리 |
|---|---|
| 확장 미설치·비활성 | 담기 버튼을 비활성화하고 설치 안내를 표시한다 |
| 검색 결과 0건 | 해당 품목을 실패로 두고 쿠팡 검색 링크를 제공한다 |
| 셀렉터 불일치 | 해당 품목을 실패로 처리한다 |
