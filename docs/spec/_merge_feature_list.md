## 2. 핵심 기능 목록

### 2.1 예측기반 발주 엔진

- 과거 매출, 날씨, 요일/공휴일, 지역 이벤트[조사 중], SNS 노출도[조사 중]를 반영한다.
- 메뉴별 1-3일 예상 수요를 예측한다.
- 필요 재고량을 계산한다.
- 초기 재고는 1회 입력한다.
- 이후 판매 메뉴의 레시피 기반으로 식자재 사용량을 자동 계산한다.

### 2.2 품목별 추천발주

- 예측 판매량을 반영한다.
- 현재 재고를 반영한다.
- 레시피 소모량을 반영한다.
- 리드타임과 안전재고를 반영한다.
- 품목별 권장 발주 수량과 예상 소진 시점을 제안한다.
- 추천 사이트로 발주 정보를 전달한다.
- 실제 결제는 외부에서 진행된다.

### 2.3 점주 승인형 운영

- AI 추천발주안을 점주가 확인한다.
- 점주가 추천안을 수정할 수 있다.
- 점주가 최종 승인할 수 있다.
- 수정 이력과 실제 판매 결과를 다음 추천 정확도 개선에 반영한다.

### 2.4 소비기한 관리

- 식자재 소비기한을 자동 관리한다.
- D-3·D-1·초과 시점에 단계별 알림을 제공한다 (상세 정책: `feature_spec.md` §5).

### 2.5 POS 어댑터

- TossPlaceAdapter를 제공한다.
- KiwoomAdapter를 제공한다.
- OKPOSAdapter를 제공한다.
- CSVAdapter를 제공한다.
- 각 POS 데이터를 Canonical Schema로 변환한다.

### 2.6 AI/예측 근거

- 이동평균, ARIMA/Prophet, XGBoost/LightGBM, LSTM, TimExer 순서로 베이스라인을 비교한다 (초기 모델은 베이스라인 비교 후 선정).
- 예측 결과에 대한 근거를 제공한다 (산출 방법·출력 형태는 별도 확정).

### 2.7 자동화 파이프라인

- n8n이 매일 02:00에 배치 워크플로우를 트리거한다.
- n8n이 DB 직접 조회/저장, 외부 API 수집, 데이터 전처리/정규화, AI Server 예측/추천발주 호출, 알림 단계를 오케스트레이션한다.
- 실패 시 Slack 알림을 제공한다.

## 확정 사항 요약

### 인증/회원
- Google / 카카오 로그인 모두 Backend가 자체 JWT 발급 (Access Token 1시간, Refresh Token 30일 HttpOnly Cookie, Rotation 적용)
- 이메일 회원가입은 email·password·name만 받고, 소셜·이메일 계정 모두 가입 직후 사업자 검증 단계로 진입 (계정은 항상 생성됨)
- 사업자 검증은 온보딩과 분리된 2단계 게이트(NTS 자동 + 관리자 승인 병행): ① 사업자번호 국세청 즉시 검증 ② 사업자등록증 업로드 → `PENDING` → 관리자 승인 → `VERIFIED`. `business_status`(UNVERIFIED/PENDING/VERIFIED/REJECTED)로 관리. **PENDING부터 온보딩 진입 허용**(1-B), 검증 실패·반려 시 계정 유지 + 재검증, 마스터 코드로 강제 패스 가능 (`security.md` §2.4)
- 관리자(`users.role=ADMIN`)는 `/admin` 심사 큐에서 등록증을 보고 승인/반려 (최소 기능, 사용자·매장 종합 관리도구는 [후속])
- 미검증·온보딩 미완료 시 재접속해도 검증/초기 설정 화면으로 강제 이동 (`business_status`·`onboarding_completed` 관리)
- 매장 정보 입력 항목: 사업자등록번호, 매장명, 업종, 연락처, 주소, 매장 규모 구간, 운영 형태 (전체 필수)
- POS 연동 실패 시 CSV 임시 모드 허용, 수요예측/자동발주 비활성화 + "POS 연동 미완료" 배지 표시

### POS 연동
- CSV 업로드는 사주라 제공 고정 템플릿 형식만 허용
- 이상치 처리 방식(자동 분리·점주 알림·복구·폐기 분기 조건)은 별도 확정 예정
- POS사별 API 자격증명 형식은 `docs/research/backend/13_pos_adapter.md`에서 조사·정의

### 메뉴 관리
- 메뉴 삭제는 소프트 삭제로 처리하고 영구 삭제하지 않음 (과거 판매 데이터 참조 보존)
- 재고 차감 사용 여부 토글 (기본값 ON), OFF 시 레시피 불필요
- 재고 차감 ON + 레시피 미입력 시 경고 표시

### 재고 관리
- 재고는 로트(입고 배치) 단위로 관리, 재고 단위 선택지 제공 (kg / g / L / ml / 개)
- 자동 차감은 소비기한 빠른 로트부터 FIFO 적용
- 재고 0 도달 시 차감 멈춤, "재고 확인 필요" 상태 표시 + 알림 + 홈 경고 배지
- 재고 수동 수정 시 사유 필수 선택 (실사 조정 / 소비기한 정정 / 기타), 수정 이력 기록
- 리드타임 / 안전재고는 재고 관리 재료 상세 화면에서 재료별 설정
- 단가: 초기 Playwright 쿠팡 최저가 자동 조회, 발주 시 자동 최신화, 수동 수정 가능
- 소비기한 D-3일 경고 알림 / D-1일 긴급 알림 / 초과 시 점주 폐기 요청 알림 (자동 폐기 없음)

### 수요예측
- 전체 메뉴 대상 예측 (재고 차감 여부 무관)
- 신뢰도 낮음 경고 기준: 예측 정확도·학습 데이터 기간·결측값 비율 기반 (지표 선정·정량 임계값 모두 AI probe 후 확정)
- Cold-start: 자체 데이터 30일 전까지 동일 업종 + 유사 상권 + 매장 규모 기준 유사 매장 예측 활용

### 추천발주
- 발주 연동 대상: 쿠팡 (이후 추가 업체 확장 고려)
- 쿠팡 장바구니 담기 실패 시 재시도 없이 즉시 점주에게 실패 품목 안내
- 추천발주 기본 산식은 AI Server 추천 모델의 베이스라인 로직으로 사용
- 단위 통일: 계산 전 기준 단위로 변환 (중량 → g / 부피 → ml / 개수 → 개)

### 대시보드
- ROI 지표: 폐기율, 재고 회전율, 예측 정확도 지표(지표 선정 미정 — research §3), 월별 폐기 비용, 전월 대비 폐기 비용 변화율
- 조회 단위: 주별 기본, 기간 선택 가능
