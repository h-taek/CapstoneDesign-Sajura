# 모델 설계서

## 1. 모델 목적

- 과거 주문 데이터와 외부 변수 데이터를 기반으로 미래 수요를 예측한다.
- 과거 발주 데이터와 수요 예측을 기반으로 미래 발주를 예측한다.
- 예측 결과의 근거를 점주가 이해할 수 있도록 설명을 제공한다 (산출 방법·출력 형태는 별도 확정).

## 2. 베이스라인 비교 순서

| 순서 | 모델 | 역할 |
|---|---|---|
| 1 | 이동평균 | baseline 1단계 |
| 2 | ARIMA / Prophet | baseline 2단계 |
| 3 | XGBoost / LightGBM | baseline 3단계 |

> **비교 완료 (M6.A5 + M6.A9)** — 나이브 2·이동평균·SARIMA·XGBoost·LightGBM + 하이브리드 변형·CatBoost 12개 후보(`AI/notebooks/04_baselines.ipynb`) + DNN 계열 4종(SeasonalNaive·Chronos-bolt·DeepAR·PatchTST, `09_dnn_probe.ipynb`). 4·5단계(LSTM/RNN·TimExer)는 동급 계열이 나이브 이하로 판명되어 별도 실험 불요 — **DNN 보류 확정(§3)**.

## 3. 초기 모델

- **초기 모델 확정 (M6.A6): LightGBM 비율 타깃 하이브리드** — 타깃 `log1p(일 매출) − log1p(직전 7영업일 평균)`, 예측 복원 `ŷ = expm1(pred + log1p(roll7))`. 수준(level)은 이동평균이 추적하고 모델은 편차(요일·학사·공휴일·기상·regime)만 학습 — 순정 GBM·SARIMA가 못 이긴 MA-7 대비 유일하게 유의미 우위(봉인 test sMAPE 30.0%, MA-7 대비 MAE -19.6%). **39차 그리드 재확인**: XGB·CatBoost에 가족별 자기 그리드(90조합)로 튜닝을 줘도 +10~11% 열세 유지, LGBM 재탐색은 채택값 대비 −0.2% 동률(독립 탐색 수렴 — 파라미터 요행 아님, `AI/notebooks/13_grid_search.ipynb`).
- 라이브러리: `lightgbm>=4.5` (AI `[ml]` extra). 하이퍼파라미터·모델 카드: `AI/notebooks/05_model_selection.ipynb` (Optuna 튜닝 확정값 + fallback 스크리닝 설정).
- **보조 baseline: MA-7**(직전 7영업일 평균) — 서빙 fallback + drift 감시 기준선.
- 1차 타깃은 **매장 일 매출** — **AI 산출 범위 확정(38차, 담당자 / 39차 구조 확정)**: 산출 구조는 **2모델** — 모델 ① 매출 예측(V1-t) + 모델 ② **매장별 메뉴 분해**("공통 분해 모델 없음" = 매장 간 통일 모델을 두지 않는다는 뜻, 매장별 분해는 유지 — 39차 담당자 정정). **재료 리스트업은 점주(사용자) 관리**(레시피 입력) — 시스템 자동 산출 아님. 메뉴 레벨 직접 시계열 예측은 이력 부족으로 기각 유지(재개장 후 신규 메뉴 49일 이하, EDA §3).
- **모델 ② 확정 (39차, M7.A3)**: **메뉴 비중 분해 — 최근 28영업일 합산 수량 비중(S1)**, 매장별 요청 이력에서 즉석 산출(stateless). 검증: 후보 4개 사전 고정 평가에서 요일 조건부·혼합이 5 fold 전패 — 요일이 바꾸는 것은 총량(①의 몫)이지 메뉴 믹스가 아님. 성능: 비중 총변동거리 0.276·top-5 메뉴 적중 73.1%·신메뉴(이력 전무) 질량 평균 1%. 역할 분담: **①은 "언제 얼마나", ②는 "무엇을"**. 산출물은 참고치 — 신뢰도 배지 동반 노출(§9 원칙). 근거: `AI/notebooks/11_menu_decomposition.ipynb`, 서빙: `AI/app/model/decompose.py` + `/ai/orders/recommend` v2(`api_spec.md` §8 — ①×②→점주 레시피 BOM 전개→재고·리드타임 반영).
- **다일 선행·예측 구간 (38차 고도화)**: 모델 우위는 D+1 -10.2% / D+2 -3.0% / D+3 +0.4%(vs MA-7, h별 개별 모델 기준)로 계단식 소멸 — 1~3일 제공 시 **선행일별 신뢰도 차등**(구간 확대·배지) 적용, D+2·3은 익일 배치에서 자동 갱신됨을 안내. **예측 구간 = LightGBM quantile P10/P90**(커버리지 78%) 채택 — 발주 안전범위·신뢰도(feature_spec §5.3) 입력. 점 예측은 l2 유지(P50 대체·앙상블 기각). 근거: `AI/notebooks/06_enhancement.ipynb`.
- **다일 서빙 전략 확정 (38차 후속, §6 실험)**: 서빙(`AI/app/model/predictor.py`)은 **h=1 단일 모델을 h-앵커 피처로 재사용** — 검증에서 h별 개별 모델보다 평균 우위(sMAPE D+2 −1.1%p·D+3 −1.0%p)로, 서빙 기준 계단은 **D+1 -10.2% / D+2 -4.1% / D+3 -1.4%**(vs MA-7). 학습 행 3배 **멀티 호라이즌 풀링은 기각**(사전 등록 규칙 위반 — D+1 +2.6%p 악화, 개강 fold 붕괴: 저용량 트리가 호라이즌 혼합 분포를 분리하지 못함) → 유효 표본 확대는 모델링 트릭이 아닌 실데이터 확보(과거분 소급·유사 매장)로만. 근거: `AI/notebooks/06_enhancement.ipynb` §6.
- **외부 검증 통과 (38차 후속)**: V1-t 레시피를 서빙과 동일 구성(고정 파라미터·60라운드·h=1 단일 모델)으로 Kaggle Recruit 일본 음식점 **814곳에 동결 이식** — 사전 등록 기준(과반 승 + 중앙값 ≤ −3%) 충족: **승률 92.6%, 상대 MAE 중앙값 −10.1%**(vs MA-7 — 파일럿 매장의 −10.2%와 일치, 주점(Izakaya) 서브셋 95.9%·−11.0%). h=1 전략은 D+3까지 우위 유지(−10.4%). **SHORT_HISTORY 60일 임계 실증**: 이력 60일 미만 구간 승률 59.1%·−1.4% → 60일 이상 79~89%·−9~−13%로 경계 불연속(feature_spec §5.3 T1 근거 보강). **B단계(같은 데이터, 사전 선언 기준)**: ① 전 매장 통합 학습(pooling)은 기존 매장에서 매장별 학습 대비 승률 53.9%로 기준 미달 → **기각, 매장별 fit-on-request 유지**(stateless 서빙 설계 지지) ② **cold-start는 기준 충족** — 이력 10~59일 구간에서 글로벌 모델 승률 72~79%·중앙값 −6~−7%(로컬 59.1%·−1.4%) → 다매장 확장 시 **"신규 매장 첫 60일 global prior → 로컬 전환" 하이브리드** 실증 근거(Phase 8+ 활성화, 현 단일 매장 MVP 미적용). 근거: `AI/notebooks/10_recruit_validation.ipynb` (데이터 로컬 전용).
- **DNN 도입 보류 확정 (38차, M6.A9)** — AutoGluon-TS 실전 probe(동일 하네스 1-step): 최고 DNN 계열 Chronos-bolt(zero-shot)가 V1-t 대비 +8.9%(사전 기준 -5% 미달), 학습형 DeepAR·PatchTST는 계절 나이브 이하. 재평가 트리거: ① 데이터 2년+ 축적 ② 다매장 확장 ③ V1-t의 MA-7 대비 skill 지속 상실(drift) ④ Chronos 계열 fine-tuning·covariates 지원 릴리스. Chronos zero-shot은 **신규 매장 cold-start 후보**로 별도 메모 — 이후 38차 후속 외부 검증에서 **GBM global prior가 더 간단한 대안으로 실증**됨(위 외부 검증 B단계). 근거: `AI/notebooks/09_dnn_probe.ipynb`. **트리거 ④는 39차에 소진**: Chronos-2(2025-10, covariates 지원 릴리스)로 재검증 — covariates 효과는 실재(univariate 대비 개선, bolt식 regime 붕괴 해소)하나 V1-t 대비 +13.9%로 사전 기준(−5%) 미달, 동반 검증한 TabPFN v2(Nature 2025, 소표본 특화)도 +29.0%(개강 fold 붕괴)로 기각 → **V1-t 유지**. 실험 전량 MLflow 대장 기록(로컬). 근거: `AI/notebooks/12_mlflow_model_comparison.ipynb`. 잔여 트리거: ①②③.

## 4. 예측 대상

- 메뉴별 1-3일 예상 수요
- 품목별 권장 발주 수량
- 예상 소진 시점

> **산출 구조 (38차 확정 + 39차 모델 ② 확정)**: ① **매장 일 매출 예측**(§3 초기 모델 + 고도화) ② **메뉴별 예상 수량 = 매장별 비중 분해**(모델 ②, §3 — 예측 매출 × 최근 28영업일 비중, 참고치) ③ **재료별 발주 참고치 = 점주 레시피(BOM) 전개 + 재고·리드타임**(결정론, `/ai/orders/recommend` v2). 재료 리스트업(레시피 등록)은 점주 관리. §4~§6의 "메뉴별 수요·추천발주" 표현 정리(참고치 성격 명시)는 담당자 검토 항목 유지.

## 7. 학습 방식

- n8n을 통해 데이터를 주기적으로 수집한다.
- 배치 학습 방식을 사용한다.
- 주간 단위 정기 재학습을 수행한다.
- **교차 검증 방식: 월 단위 Walk-forward** (검증 fold = 영업일 10일 이상 월, 최종 fold는 test 봉인 — M6.A4 확정, `ml_pipeline.md` §6). 매장별 단일 시계열이므로 무작위 K-fold 금지.
- **평가 지표 (M6.A6 확정): MAE(주 지표·모델 선정 기준) + sMAPE(보고용).** MAPE는 소액 매출일의 분모 왜곡으로 제외(구 후보 MAE+MAPE+R²에서 정정). 운영 목표(상대 기준): **naive-요일 대비 skill ≥ +15%, MA-7 우위 유지** — 미달 시 drift 경보(`ml_pipeline.md` §10 연계).
- 학습 데이터 사용 방식 확정 (38차): **expanding window(전체 이력 학습), 슬라이딩 윈도우 미적용** — `ml_pipeline.md` §2 참조(재검토 조건 포함).
- 판매 결과 및 폐기 데이터를 모델 업데이트에 반영한다.
- 점주 수정 이력을 재학습에 반영한다.

## 8. 예측 방식

- 사전 배치 계산 후 DB에 저장한다.
- 사용자 요청 시 DB에 저장된 결과를 즉시 반환한다.
- 저장 결과가 없으면 AI Server 직접 호출 후 결과를 저장한다.

## 9. 예측 근거 설계

- 예측 결과의 근거를 점주가 이해할 수 있도록 제공한다.
- **예측 근거 산출: LightGBM `gain` (1차 스크리닝) → TreeSHAP (`shap.TreeExplainer`) 확정.**
- **출력 형태 확정 (38차, M6.A7)**: **top-3 기여 요인**(방향 + 상대 기여 %) + **rule-based 자연어 1문장** — "평소(직전 7영업일 평균) 대비 ±X%" 프레임. 편차 모델(§3)의 SHAP 합이 곧 예측 편차라 문장과 수학이 일치. **자연어 변환은 LLM 미사용**(템플릿 — 결정론·무비용). 응답 스키마 `{date, deviation_vs_baseline, baseline, top_factors[{feature,label,pct}], sentence}` — 근거·prototype: `AI/notebooks/07_xai.ipynb`.
- 예측 근거는 신뢰도 배지·P10/P90 구간과 **항상 동반 노출**(단독 금지) — 공휴일 등 특수일은 학습 표본이 적어 설명 신뢰가 낮음(M6.A7 실측).
- 신뢰도 경고 기준은 `feature_spec.md` §5.3 참조.
