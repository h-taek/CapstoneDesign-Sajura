# AI 설계서

> 모델과 파이프라인의 확정 사항. 비교·실측·기각 이력은 `docs/research/ai/01_model_selection.md`·`02_preprocessing.md`를 본다.

---

## 1. 목적

- 과거 판매 데이터와 외부 변수로 미래 수요를 예측한다.
- 예측 결과와 재고·레시피로 발주 참고치를 산출한다.
- 예측 결과의 근거를 점주가 이해할 수 있도록 제공한다.
- 수요예측과 발주 참고치를 사용자 요청 전에 사전 생성해 DB에 저장하고, 요청 시 즉시 반환한다.

---

## 2. 예측 대상

산출 구조는 3단이다.

| 단계 | 산출 | 방식 |
|---|---|---|
| ① | 매장 일 매출 예측 | 모델 ① (§3) |
| ② | 메뉴별 예상 수량 | 모델 ② 매장별 비중 분해 — ①의 예측 매출 × 비중 (참고치) |
| ③ | 재료별 발주 참고치 | 점주 레시피(BOM) 전개 + 재고·리드타임 (결정론, `/ai/orders/recommend` v2) |

- 모델 ①은 "언제 얼마나", 모델 ②는 "무엇을" 담당한다.
- 재료 리스트업(레시피 등록)은 점주가 관리한다. 시스템이 자동 산출하지 않는다.
- 메뉴 레벨 직접 시계열 예측은 이력 부족으로 적용하지 않는다.
- ②·③의 산출물은 참고치이며 신뢰도 배지를 동반해 노출한다(§8).

## 3. 모델

### 3.1 모델 ① 매출 예측

- **LightGBM 비율 타깃 하이브리드 (V1-t)** — 타깃 `log1p(일 매출) − log1p(직전 7영업일 평균)`, 예측 복원 `ŷ = expm1(pred + log1p(roll7))`. 수준(level)은 이동평균이 추적하고 모델은 편차(요일·학사·공휴일·기상·regime)만 학습한다.
- 라이브러리: `lightgbm>=4.5` (AI `[ml]` extra). 하이퍼파라미터 확정값·모델 카드: `AI/notebooks/05_model_selection.ipynb`.
- **보조 baseline: MA-7**(직전 7영업일 평균) — 서빙 fallback + drift 감시 기준선.
- DNN은 도입하지 않는다. 재평가 트리거는 ① 데이터 2년 이상 축적 ② 다매장 확장 ③ MA-7 대비 skill 지속 상실이다.

### 3.2 모델 ② 메뉴 비중 분해

- **최근 28영업일 합산 수량 비중(S1)** — 매장별 요청 이력에서 즉석 산출한다(stateless).
- 서빙: `AI/app/model/decompose.py`.

### 3.3 다일 선행

- 1~3일을 제공하며 **선행일별 신뢰도를 차등** 적용한다(구간 확대·배지). D+2·D+3은 익일 배치에서 자동 갱신됨을 안내한다.
- **예측 구간 = LightGBM quantile P10/P90**. 발주 안전범위·신뢰도(`04_feature_spec.md` §5.3)의 입력이다.
- 서빙은 **h=1 단일 모델을 h-앵커 피처로 재사용**한다 (`AI/app/model/predictor.py`).

### 3.4 학습 단위

- 매장별 fit-on-request를 유지한다. 전 매장 통합 학습(pooling)은 적용하지 않는다.

## 5. 전처리

- POS별 원본을 어댑터로 수집해 Canonical Schema로 변환하고 Pydantic으로 형식을 검증한다.
- **타깃 이상치**: log1p 스케일 IQR k=3.0. 각 학습 배치의 train 구간에 fit하고 경계 밖 값은 경계로 캡(winsorize)한다. 피처는 실측이므로 별도 처리하지 않는다.
- **결측값**(컬럼별)
  - 기상 NA → 캘린더 선형 보간
  - 유동인구(월간) → 전월 값 ffill + staleness 플래그. 선형 보간은 누수이므로 금지한다
  - 타깃 lag·rolling 워밍업 NaN → 트리 모델은 네이티브 NaN 유지, 선형·통계 모델만 core lag 완비 행 사용
- **누수 방지**: 보간·통계 계산의 기준값은 현재 배치 이전 train 구간에서만 산출한다.
- 구현(SSOT): `AI/data_prep/preprocess.py`. 후보 비교는 `docs/research/ai/02_preprocessing.md`.

---

## 6. 학습

- 배치 학습. 주간 단위 정기 재학습을 수행한다.
- **학습 데이터 사용 방식: expanding window**(전체 이력 학습). 슬라이딩 윈도우는 적용하지 않는다.
- **교차 검증: 월 단위 walk-forward** — 검증 fold는 영업일 10일 이상인 월, 최종 fold는 test로 봉인한다. 매장별 단일 시계열이므로 무작위 K-fold를 금지한다.
- **평가 지표: MAE**(주 지표·모델 선정 기준) **+ sMAPE**(보고용). MAPE는 소액 매출일의 분모 왜곡으로 제외한다.
- **운영 목표**(상대 기준): naive-요일 대비 skill ≥ +15%, MA-7 우위 유지. 미달 시 drift 경보(§10).
- 판매 결과·폐기 데이터·점주 수정 이력을 재학습에 반영한다.

## 7. 출력·예측

### 7.1 출력

- 메뉴별 1~3일 예상 수요 (참고치)
- 재료별 발주 참고치
- 예측 근거 (§8)
- 예측 신뢰도 낮음 경고 배지

### 7.2 예측 방식

- 사전 배치로 계산해 DB에 저장한다.
- 사용자 요청 시 저장된 결과를 즉시 반환한다.
- 저장 결과가 없으면 AI Server를 직접 호출하고 결과를 저장한다.

## 8. 예측 근거

- **산출: LightGBM `gain`(1차 스크리닝) → TreeSHAP(`shap.TreeExplainer`).**
- **출력 형태**: top-3 기여 요인(방향 + 상대 기여 %) + rule-based 자연어 1문장 — "평소(직전 7영업일 평균) 대비 ±X%" 프레임. 자연어 변환에 LLM을 쓰지 않는다(템플릿).
- 응답 스키마: `{date, deviation_vs_baseline, baseline, top_factors[{feature,label,pct}], sentence}`
- 예측 근거는 신뢰도 배지·P10/P90 구간과 **항상 동반 노출**한다. 단독 노출을 금지한다.
- 신뢰도 경고 기준은 `04_feature_spec.md` §5.3을 따른다.
