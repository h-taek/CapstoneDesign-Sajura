# ML 파이프라인 설계서

## 1. 파이프라인 목적

수요예측과 추천발주를 사용자 요청 전에 사전 생성하여 DB에 저장하고, 사용자 요청 시 즉시 반환할 수 있도록 한다.

## 2. 실행 방식

- n8n 기반 야간 배치 자동화 파이프라인을 사용한다.
- 매일 02:00 자동 실행한다.
- 주간 단위 정기 재학습을 수행한다.
- 학습 데이터 사용 방식 확정 (38차): **expanding window** — 전체 이력 학습, 슬라이딩(rolling) 윈도우 미적용. rolling 90~180일은 검증에서 +15~17% 열세(regime 구간 붕괴 — 과거 데이터를 버리면 표본 부족이 더 아픔). 재검토 조건: 데이터 2년+ 축적 또는 MA-7 대비 skill 지속 하락(drift). 근거: `AI/notebooks/06_enhancement.ipynb` §3.

## 3. 파이프라인 단계

```text
수집(POS API)
→ 전처리(결측·이상치 검증·표준화)
→ 학습(주간 재학습, 모델은 research §2 확정)
→ 예측(내일 발주량 계산)
→ 캐싱(DB 저장, 즉시 응답 대비)
→ 알림(앱 내 알림)
```

## 6. 전처리

- POS별 원본 데이터를 어댑터로 수집한다.
- Canonical Schema로 변환한다.
- JSON Schema 또는 Pydantic으로 형식을 검증한다.
- 결측, 이상치, 표준화를 처리한다.
- 이상치 탐지 (M6.A4 확정): 타깃(일 매출)은 **log1p 스케일 IQR k=3.0** — 각 학습 배치의 train 구간에 fit하고 경계 밖 값은 경계로 캡(winsorize). 파일럿 데이터 기준 개입 0건. raw 스케일·k=1.5·P1/P99 캡은 실수요 오탐으로 기각. 피처(기상 극값 등)는 실측이므로 별도 처리 없음.
- 결측값 처리 (M6.A4 확정, 컬럼별):
  - 기상 NA → 캘린더 선형 보간 (과거 실측 구간이라 방향 제약 없음)
  - 유동인구(월간) → 전월 값 **ffill(직전 가용 월) + staleness 플래그**. 선형 보간은 누락 월의 다음 달 값을 참조하므로 금지(서빙 시점 미확정 = 누수)
  - 타깃 lag·rolling 워밍업 NaN → 트리 모델은 네이티브 NaN 유지, 선형·통계 모델만 core lag(lag1·roll7·lag_dow) 완비 행 사용
- 검증 분할 (M6.A4 확정): **월 단위 walk-forward** — 검증 fold = 영업일 10일 이상인 캘린더 월, train = 해당 월 이전 전체 영업일, 최종 fold는 test로 봉인. 휴업 월은 규칙상 자동 배제된다.
- **누수 방지**: 보간·통계 계산에 사용하는 기준값은 현재 배치 이전 train 구간 데이터에서만 산출한다.
- 근거·후보 비교: `AI/notebooks/03_preprocessing.ipynb` · 구현(SSOT): `AI/data_prep/preprocess.py`

## 7. 학습

- 초기 AI 모델은 미확정 (베이스라인 비교 후보 중 선정).
- 주간 단위 정기 재학습을 수행한다.
- 판매 결과와 폐기 데이터를 반영한다.
- 점주 수정 이력을 재학습에 반영한다.

## 8. 예측

- 메뉴별 1-3일 예상 수요를 예측한다.
- 예측 결과를 DB에 저장한다.
- 추천발주안을 사전 생성하여 DB에 저장한다.
- 저장된 결과가 있으면 사용자 요청 시 DB에서 즉시 반환한다.
- 저장된 결과가 없으면 AI Server를 직접 호출하고 결과를 저장한다.

## 9. 예측 근거 생성

- 예측 결과와 함께 점주가 이해할 수 있는 근거를 생성한다.

- 예측 신뢰도가 낮으면 경고 배지를 함께 표시한다.
