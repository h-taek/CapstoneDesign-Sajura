# POS 어댑터 — API 연동 조사

> **상태**: 토스플레이스 조사·실측 기록(§3). 키움페이·OKPOS 조사 전
> **목적**: POS API 연동(토스플레이스·키움페이·OKPOS) 조사 항목. 항목은 외부 POS사 API 문서·테스트 환경·자격증명 발급 절차를 확보해야 확인할 수 있는 probe 의존 정보다.
> **연결 spec**: `docs/spec/01_basic_design.md` §3.4.2·§3.4.3, `docs/spec/02_implementation_design.md` §1.3·§3.3

---

## 1. 조사 대상 POS사

토스플레이스, 키움페이, OKPOS 3사.

---

## 2. 조사할 항목 (probe 체크리스트)

각 POS사에 대해 다음을 확인한다.

### 2.1 인증 / 자격증명

| 확인 항목 | 비고 |
|---------|------|
| 인증 방식 | API Key / OAuth 2.0 / 매장 코드+비밀번호 / 클라이언트 인증서 등 |
| 자격증명 필드 구조 | `pos_connections.api_key` 단일 컬럼으로 충분한가, 추가 컬럼이 필요한가 |
| 자격증명 발급 절차 | 점주 직접 발급 가능 / 영업팀 경유 필수 / 가맹점 신청 필요 |
| 갱신 주기 | 토큰 만료·자격증명 회전 정책 |
| 테스트 환경 (Sandbox) | 별도 SDK·DSN 제공 여부 |

### 2.2 데이터 수집 방식

| 확인 항목 | 비고 |
|---------|------|
| Webhook 지원 | 실시간 결제 이벤트 push 가능 여부 |
| Polling 주기 | 가능 / 최소 간격 / Rate limit |
| 백필 범위 | 과거 N개월 조회 가능 / 일별 / 월별 |
| 응답 포맷 | JSON / XML 등 |
| 에러 응답 표준 | HTTP 상태 코드 + 코드 매핑 |

### 2.3 공통 스키마 매핑

`01_basic_design.md` §3.4.5 사주라 공통 스키마에 매핑할 때 다음을 확인한다.

| 확인 항목 | 비고 |
|---------|------|
| 메뉴 매핑 단위 | POS의 상품 ID·SKU vs 사주라 `menu_name` |
| 메뉴명 변형 처리 | 공백·대소문자·POS사 표기 차이 |
| 결제 취소·환불 이벤트 | 별도 이벤트 / 음수 amount / soft delete |
| 외부 영수증 ID | `sale_records.external_sale_id` 매핑 — 중복 방지 (`02_implementation_design.md` §4.4 UNIQUE) |
| 시간대 처리 | POS사 응답 시각이 KST인지 UTC인지 |

### 2.4 운영 고려사항

| 확인 항목 | 비고 |
|---------|------|
| 약관 / SLA | API 사용 제한·서비스 보장 수준 |
| 비용 | 호출당 비용 / 월정액 / 무료 한도 |
| 데이터 소유권 | 매장 데이터에 대한 POS사 정책 |
| 한국 개인정보보호법 | API 응답에 포함된 개인정보(이름·전화번호 등) 처리 |

## 3. 토스플레이스 조사 결과

출처: 토스플레이스 Open API 연동 구현(PR #39)과 칠야 매장 실데이터 동기화(2026-11-01).

### 3.1 인증 / 자격증명

| 항목 | 관찰 |
|---|---|
| 인증 방식 | 사주라 앱(토스플레이스 개발자센터 '내 애플리케이션 > 인증 정보')의 Access Key·Secret을 헤더 `x-access-key`·`x-secret-key`로 보낸다. 키는 매장마다 따로 발급되지 않고 앱 하나에 하나다 |
| 매장 연결 | 점주가 토스 POS 설정 > 서비스 연동에 사주라 서비스 코드를 넣어 매장을 연결한다. 사주라는 가맹점 ID(MerchantId)로 그 매장을 조회한다 |
| 자격증명 필드 구조 | 매장별로 저장할 값은 가맹점 ID 하나다. `pos_connections.store_code`(VARCHAR(50))에 들어가고 `api_key`는 쓰지 않는다 |
| 발급 절차 | 새 매장 연결에는 토스 앱 검수와 VAN 대리점 활성화가 필요하다. 점주가 가맹점 ID를 확인하는 방법은 토스에 문의 중이다 |
| 소유 확인 | 앱 키로 사주라에 연결된 모든 가맹점을 조회할 수 있다. 입력한 가맹점 ID가 그 점주의 매장인지 확인할 수단(가맹점 정보 응답의 사업자등록번호 포함 여부 등)은 확인하지 않았다 |
| 갱신 주기·테스트 환경 | 확인하지 않았다 |

### 3.2 데이터 수집 방식

| 항목 | 관찰 |
|---|---|
| 주문 조회 | `GET {base}/merchants/{merchantId}/order/orders?from&to&page&size&orderStates`. base는 `https://open-api.tossplace.com/api-public/openapi/v1` |
| 조회 기준 시각 | `from`·`to`는 결제 내역이 바뀐 시각 기준이다. 나중에 취소된 주문은 취소 시각 범위에서 다시 내려온다 |
| 페이지 | `size=100`으로 받아 100건보다 적게 오면 마지막 페이지다 |
| 응답 포맷 | JSON `{ resultType: SUCCESS / FAIL, success, error: { reason, message, errorCode } }` |
| 웹훅·Rate limit·백필 한계 | 확인하지 않았다 |

### 3.3 공통 스키마 매핑

| 항목 | 관찰 |
|---|---|
| 주문 상태 | `orderState` = `COMPLETED` / `CANCELLED` / `OPENED` 등 |
| 메뉴 | `lineItems[].item.title`(메뉴명), `quantity` |
| 가격 | `itemPrice.priceValue`(기본가), `optionChoices[].priceValue`·`quantity`(옵션), `appliedDiscounts[].amount`(품목 할인) |
| 영수증 ID | 주문 `id`. 주문 한 건에 품목 줄이 여럿이다 |
| 시간대 | `completedAt`·`createdAt`이 UTC(`Z`)로 온다 |

### 3.4 실측 (칠야, 2026-11-01)

| 항목 | 값 |
|---|---|
| 첫 동기화(2025-04~2026-10) | 판매 15,176행, 16.7초 |
| 바로 다시 동기화 | 0건 |
| 기존 엑셀 대비 일별 상관 | 달력 날짜 기준 0.745, 새벽 6시 마감으로 묶으면 0.990 |
| 기존 엑셀 대비 합계 | −3.5% (6시 마감 기준). 할인·봉사료·부분 취소 처리 차이로 추정하며 원본 대조 전이다 |
